Publish `projection-discovery-dispatch.yml` as `.github/workflows/projection-discovery-dispatch.yml` on `ci/qualified-device-delivery`. Publish a reviewed request as `ci/projection-discovery-request.json` in the same commit, replacing the example SHA and nonce. The workflow fetches that file at the push commit, verifies its Git blob and the fixed diagnostic branch head, then sends one supported `workflow_dispatch` request using the job's short-lived `GITHUB_TOKEN`. It does not check out or execute repository code, consume repository secrets, compile an application, cancel jobs, or retry a POST.

The only target is `archive-integration.yml` at `diagnostics/c55-projection-deferred`, scope `projection-discovery-only`, unsigned-device disabled, retained run `42160468600` and source `c55e19c4f5cbe0d730499035d0a0ef712f6903a9`. The retained payload is the existing artifact `13482555818`; the target workflow verifies its provenance. No request can supply API endpoints, workflow names, refs, scope, tokens, or build flags.

HTTP 204 records submission only. The repository integration must independently verify the actual run, exact head SHA and job allocation: the branch can move between its head check and GitHub accepting the dispatch. A transport error after POST is `submissionUnknown`; it must be checked through read-only run metadata before any new request. Missing final output after an interrupted submit step is also potentially submitted and requires the same reconciliation. Rerunning the bridge is rejected (`GITHUB_RUN_ATTEMPT` must be 1). A deliberately new request should use a fresh nonce and reviewed push. Nonce freshness is an operator convention, not durable deduplication: another push can intentionally submit the same request again. Concurrency preserves active bridge jobs but GitHub replaces older pending bridge jobs with newer pushes; this is not a FIFO queue. The target workflow keeps its existing native qualification queue.

An organization or repository policy may deny `actions: write`. The bridge reports only `githubPermissionDenied` and never prints credentials, HTTP bodies or exception details. Such a denial is a genuine permissions blocker; no personal-token workaround is included. GitHub supports `workflow_dispatch` triggered with `GITHUB_TOKEN` as an exception to the usual recursive-workflow restriction: https://docs.github.com/en/actions/how-tos/writing-workflows/choosing-when-your-workflow-runs/triggering-a-workflow#triggering-a-workflow-from-a-workflow

Run the portable mocked and static checks with `python3 -W error -m unittest -v test_dispatch_bridge.py` from this directory. They perform no network requests or GitHub mutations.
