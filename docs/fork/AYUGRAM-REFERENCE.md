## Architecture and reference limitations

AyuGram is an exteraGram-derived Telegram Android fork (`README.md:9`), not an iOS library. Android UI fragments/RecyclerView, Java controllers, SharedPreferences, Room DAOs and native JNI networking are separate integration surfaces. The requested native client should implement equivalent requirements against Telegram-iOS components; there is no direct Java-to-Swift mapping.

The public root checkout is incomplete for message capture/rendering: `.gitmodules:1` references `AyuGram/AyuGram4A_proprietary` at gitlink `a3b47ff3af30829cdec58d61d61ebc0a64546563`; it is uninitialized here. `README.md:102` explicitly instructs builders to implement `AyuMessageUtils` and `AyuHistoryHook`. The code imports these helpers but their definitions are absent from the inspected checkout. This audit does not claim their implementation, license terms or accessibility were verified. Do not obtain or reverse engineer those classes as a shortcut; design native behavior from documented requirements and observable public call sites.

The Android fork's claim of “full ghost mode” is not evidence of anonymity or protocol-level invisibility. Other sessions and server-derived activity can remain visible. Its claims also exceed what can be verified from this incomplete checkout.

## Privacy and security differences that must not be copied

- The Android archive is a separate Room database with edited/deleted/reaction entities, schema version 21 (`ayu/database/AyuDatabase.java:20`). `ayu/database/AyuData.java:28` enables main-thread queries and destructive migration fallback; it does not configure database encryption in this constructor. This is not proof of device storage insecurity, but gives no evidence of archive-specific encryption. iOS should use reviewed native storage protection and migration behavior, keep payloads out of logs/crash reports, and test locked-device and logout handling.
- Attachments are saved beneath public Downloads (`ayu/messages/AyuMessagesController.java:35`). iOS archive files should remain inside protected application storage and be excluded from cloud/device backups as required by the strict local-only policy. Explicit export must remain outside the initial scope.
- AyuSync has an OkHttp REST client, WebSocket client, token and device registration (`ayu/sync/AyuSyncController.java:39`, `:137`; `AyuSyncWebSocketClient.java:51`). It defaults off (`ayu/AyuConfig.java:115`). Read-state serialization/transmission is active (`AyuSyncController.java:288`); the edited-history loop is **commented out** at `:266`. README describes syncing history, but this checkout does not establish that the archive sync implementation works. Exclude the entire AyuSync component from the iOS design; no third-party archive or read-state endpoints are needed.
- AyuSync supports unencrypted `http://`/`ws://` via configuration (`ayu/sync/AyuSyncConfig.java:15`) and constructs a profile URL with token in the query (`:43`). Neither behavior belongs in this client.
- README expressly discloses Crashlytics (`README.md:49`). `TMessagesProj/build.gradle:24` includes Google measurement; `:29–35` includes Firebase Crashlytics, Analytics, Messaging, Config and DataTransport. The requested iOS client must not inherit these dependencies or telemetry.
- Gradle additionally declares Room, Gson, Guava, OkHttp and an external websocket library (`TMessagesProj/build.gradle:46`, `:63`, `:68`). Version declarations alone do not verify dependencies. Do not import Android dependencies to iOS. The fork also includes a local verification AAR (`:71`), requiring separate provenance review if ever considered; it is not needed here.
- `AyuFilter` uses global caches keyed only by dialog/message (`:23`, `:74`), so cross-account identity collisions and stale results after edits/rule changes warrant explicit tests in the native design. Regex compilation at `:35` does not catch syntax exceptions locally; validation may occur in UI, but should not be the only boundary.
- Saving deleted messages and edits defaults on in Android (`ayu/AyuConfig.java:82`). Native defaults should make retention explicit and provide immediate purge. Secret-chat/TTL/view-once content needs a separately documented policy before implementation to avoid silently defeating expiration semantics.
