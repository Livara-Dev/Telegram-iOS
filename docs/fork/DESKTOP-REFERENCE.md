This is a C++/Qt Telegram Desktop fork. Its `ayu/` module adds settings, SQLite storage, filtering, forwarding and UI helpers integrated into upstream `api/`, `data/`, `history/`, and `window/` components. It supplies requirements and observable source patterns, not code to translate or an iOS networking replacement.

## Encryption, export and network distinctions

The archive constructor uses bundled SQLite/sqlite_orm at `ayu/data/ayu_database.cpp:19`, text columns at `:61` and `:97`, and WAL/SHM files handled at `:219`. No archive key setup, authenticated encryption, encrypted archive import/export, secure deletion or backup exclusion was established. Existing Telegram authorization/tdata encryption does not automatically prove encryption of this independent SQLite file.

`ayu/features/forward/ayu_sync.cpp` is misleading if read by filename alone: its `AyuSync` namespace contains synchronous Telegram download/upload/send helpers for forwarding (see `ayu_sync.h:25` and `ayu_forward.cpp:369`, `:437`). It is **not evidence of Android AyuSync cloud archive synchronization** and supplies no reviewed end-to-end encrypted archive protocol.

Filter export is distinct from archive export. `ayu/features/filters/filters_utils.cpp:345` serializes filter settings and `:366` publishes them to `https://dpaste.com/api/v2/`; `:293` imports from a supplied URL. Neither behavior should be inherited for a local-only iOS client. Local file import/export can be designed separately with explicit user action and integrity checks.

Other desktop features use third-party services: translator implementations POST to Google (`ayu/features/translator/implementations/google.cpp:28`, `:113`) or Yandex (`yandex.cpp:78`, `:95`); language downloads use jsDelivr (`ayu/ayu_lang.cpp:121`); artwork lookup uses iTunes (`ayu/ui/utils/itunes_search.cpp:698`). This audit does not establish telemetry or automatic archive uploads, but demonstrates why copying the desktop networking feature set would violate the intended minimal network boundary. Archive text must never be routed into online translation, paste export, crash logs or plugins without a separately authorized and reviewed design.
